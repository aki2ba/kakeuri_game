# 与信ゲーム（仮題）設計書 v4

掛取引の商習慣と、債権の保全・回収に関わる法令を、遊びながら学ぶためのゲームの設計書。

- **バージョン**: 4.0
- **日付**: 2026-07-31
- **位置づけ**: v3（`docs/archive/design-v3.md`）の全面書き直し。v3 の実装（`index.html`）は**放棄する**
- **スコープ**: 本書は設計のみ

## 0. なぜ書き直すのか ―― v3 の失敗分析

v3 は完成し、遊べる状態まで実装した。**面白くなかった。** 原因は3つで、いずれも構造的なものだった。

### 失敗1: 結論だけ渡して、根拠を渡していなかった

v3 の与信判断画面は「信用スコア 67」という**結論**を提示していた。67 という数字から推論できることは何もない。だからプレイヤーは必要限度を計算して決定を押すだけの作業になり、「どうすればいいのか分からない」という感想になった。

**見抜く楽しさは、照合できる材料があるときにしか生まれない。**

### 失敗2: 決着までが遠すぎた

1件の与信判断の答えが出るまで 9〜22 ターンかかった。しかも1ターンあたり、仕入方針・在庫・価格転嫁・資金繰り・回収と管理項目が多く、3分近くかかる。**主役であるはずの与信判断が事務作業に埋もれ、結果が返るころには何を判断したか覚えていない。**

ラグ自体が悪いのではない。**ラグ × 1ターンの重さ**が悪い。

### 失敗3: 伏線は仕込んだが、回収する側の記憶がなかった

v3 は「第9ターンの契約が第18ターンに効く」「回収画面に『第9ターンなら3ptで取れました』と出る」という仕掛けを実装しており、**設計どおり動いていた**。それでも刺さらない。

伏線は、プレイヤーが**あの時の違和感を持っていた**ときにだけ回収できる。兆候を見せていなければ、思い出す対象がない。**この仕掛けは失敗1に依存していて、単独では空振りする。**

### したがって v4 の方針

| v3 | v4 |
|---|---|
| スコアという結論を渡す | **兆候を渡し、プレイヤーが結論を出す** |
| 正解を当てる（交渉余地を推測する決定論クイズ） | **確率に賭ける。外しても納得できる** |
| 決着まで 9〜22 ターン | **決着まで 2〜4 ターン、1ターンは1分以内** |
| 36ヶ月・管理項目8種 | **12ヶ月・判断は与信のみ** |

「推理ゲームを作らない。**見抜きはシステム生成、判断は賭け、結果は経営に返す。**」

## 1. 一言でいうと

**取引先の書類と噂から危険を見抜き、いくら賭けるかを決め、12ヶ月の純利益を競うゲーム。**

粗利は16%しかない。**1件焦げると、同じ規模の取引5件分の儲けが消える**（§4 で検算する）。全部受ければ必ず潰れ、全部断っても経費で潰れる。**見抜いた分だけ黒字になる。**

1判断あたり30秒〜1分。1ラン12ヶ月＝約36件の判断＝**15〜20分**。

## 2. 設計の3原則

### 原則1: 兆候はシステムが生成する。シナリオは書かない

取引先は**隠れた真の状態**（健全／資金繰り悪化／破綻寸前／取り込み詐欺／架空循環／反社）を持ち、そこから**兆候（シグナル）が確率的に生成される**。シナリオを書かずに、毎回違う「見抜き」が生まれる。

兆候は2層にする。**この2層構造が本作の中核である。**

| 層 | 性質 | 何を表現するか | 遊びとしての快感 |
|---|---|---|---|
| **確定矛盾**（hard） | 書類間の論理的な食い違い。見つければ**黒が確定する** | 詐欺・架空取引・反社。人為的に作られた嘘は、必ずどこかで辻褄が合わない | Papers, Please 型の「見つけた！」 |
| **確率兆候**（soft） | 危険度を動かすだけ。単独では断定できない | 資金繰りの悪化。悪化は嘘ではなく事実なので、矛盾しない | ポーカー型の「たぶん危ない」 |

実務の与信もこの2層でできている。**詐欺は矛盾で見抜き、資金繰りの悪化は兆候の積み重ねで推し量る。** 別の技術なので、ゲームでも別の層にする。

### 原則2: 当てるのではなく、賭ける

判断は「正解を選ぶ」ではなく「**いくら賭けるか**」。外れても詰まらない。損をして、次で取り返す。

- 受ければ粗利が入るが、飛べば原価が消える
- 現金前払いを求めれば安全だが、しばしば失注する
- 断れば損はしないが、経費は毎月出ていく

**3つとも代償がある**ようにするのが要件。「断る」が常に安全なら、ゲームは成立しない。

### 原則3: 結果は経営に返る。ただし憶えているうちに返す

決着は **2〜4ターン後**。1ターンが1分以内なので、体感では数分。「あのとき本店移転が引っかかったんだよな」を憶えている距離に収める。

決着時には必ず**答え合わせ**を出す。真の状態、自分が見た兆候、**買わなかった調査で見えたはずの兆候**。ここが学習の中心であり、v3 で最も欠けていた部分である。

## 3. ゲームの構造

### 3.1 ラン

**1ラン = 12ヶ月。** 各月に案件が 2〜4 件（平均3件）。1ランで約36件を判断する。

12ヶ月を終えたときの**純利益**がスコア。運転資金が尽きたらその時点で終了（＝倒産）。

### 3.2 1ターン（1ヶ月）の流れ

```
┌─ 月初 ────────────────────────────────────────────┐
│                                                        │
│  ① 案件が 2〜4 件届く                                  │
│     ・新規の引合い                                     │
│     ・継続案件（過去に受けた相手からの追加注文）        │
│                                                        │
│  ② 調べる（調査ポイント 3pt／月）                      │
│     登記 1pt ／ 現地 1pt ／ 同業に聞く 1pt ／ 信用調査 2pt│
│     ★ 全部は調べられない。誰を疑うかを選ぶ             │
│                                                        │
│  ③ 1件ずつ判断する                                    │
│     受ける（金額を決める＋保全を要求するか）           │
│     現金前払いを要求する                               │
│     断る                                               │
│                                                        │
│  ④ 月末処理（自動・数秒）                              │
│     入金 → 運転資金が戻る                              │
│     焦げ付き → 答え合わせが出る ★ここが学習の中心      │
│     経費を引く                                         │
│     ★ 運転資金がマイナス → 倒産                        │
│                                                        │
└─ 翌月へ ─────────────────────────────────────────┘
```

**プレイヤーが触るのはこれだけ。** 仕入方針、在庫、価格転嫁、従業員、決算、税、手形割引、ファクタリングは**すべて廃止する**（§12）。

### 3.3 運転資金 ―― 現金と与信枠を1本にする

v3 は「現金」「総与信枠」「売掛残高」「在庫」を別々に管理させ、関係が分かりにくかった。v4 は**運転資金**という1つの数字に統合する。

```
出荷したとき   運転資金 −= 原価（= 売価 × (1 − 粗利率)）   ← 仕入代金を先に払う
入金したとき   運転資金 += 売価                            ← 差額が粗利
焦げたとき     運転資金 += 回収額のみ                      ← 原価がまるごと消える
毎月           運転資金 −= 経費
```

この1本で3つが同時に表現できる。

- **サイトが長い＝資金が長く塞がる**。同じ資金で売れる量が減る
- **黒字倒産**＝帳簿上は利益が出ているのに、資金が塞がって次が売れなくなり、経費で削れて死ぬ
- **焦げ付きの重さ**＝粗利ではなく原価が消える

## 4. 経済モデル（数値）

| 項目 | 値 |
|---|---|
| 開始時の運転資金 | **4,000万円** |
| 粗利率 | 案件ごとに **12〜20%**（既定16%） |
| 月次経費 | **100万円** |
| 案件の金額 | 150〜800万円（平均450万円） |
| 案件数 | 月 2〜4 件（平均3件） |
| 期間 | 12ヶ月 |

### 検算1: 1件焦げると何件分の儲けが消えるか

```
売価 450万・粗利16% → 原価 378万、粗利 72万
焦げて回収0%なら 378万 の損失
378 ÷ 72 = 5.25
```

**1件焦げると、同じ規模の取引5件分の儲けが消える。** この一文をタイトル画面とチュートリアルに出す。

### 検算2: 見抜かないと必ず潰れる

無差別に全件受けた場合の期待焦げ率は **24.4%**（§5.1 の表から算出）。

```
月3件・450万 → 売上1,350万／月
粗利  1,350 × 16%       = 216万
焦げ  1,350 × 24.4% × 0.84（原価）× 0.7（平均未回収率） ≒ 194万
経費                     = 100万
→ 月 −78万。12ヶ月で −936万
```

健全な相手だけを選べた場合（焦げ率3%）:

```
粗利 216万 − 焦げ 24万 − 経費 100万 = 月 +92万 → 12ヶ月で +1,104万
```

**見抜けば黒字、見抜けなければ赤字。** これが数字で担保されている。中途半端に半分見抜けると収支トントンになり、そこから伸ばせるかがスコアアタックになる。

### 検算3: 資金は足りるか

```
月3件・450万 → 月の原価 1,134万。平均サイト2ヶ月なら 2,268万 が常時拘束される
開始 4,000万 に対して余裕は 1,700万ほど
```

長サイトの案件（実効4ヶ月）を続けて取ると拘束が跳ね上がり、資金が尽きる。**サイトの判断が資金繰りに直結する。**

### 長サイト案件のトレードオフ

サイトが長い案件は**粗利率を高く**設定する（実効サイト1ヶ月ごとに +1pt、上限 +4pt）。実務でも長期債権には利幅が乗る。

これで「長いサイトは儲かるが資金を食う」という判断が毎回発生する。**サイトの計算式は判断画面に常時展開する**（v3 で好評だった要素なので残す）。

## 5. 取引先の生成

### 5.1 真の状態（プレイヤーには見えない）

| 真の状態 | 出現率 | 焦げる確率 | 焦げたときの基準回収率 |
|---|---|---|---|
| 健全 | 55% | 3% | 40〜80% |
| 資金繰り悪化 | 24% | 30% | 20〜70% |
| 破綻寸前 | 10% | 75% | 10〜50% |
| **取り込み詐欺** | 5% | **100%** | **0%（保全があっても0%）** |
| **架空循環取引** | 3% | **100%** | **0%（債権自体が架空）** |
| 反社会的勢力 | 3% | 0% | ―（取引すると別の罰則。§8.4） |

回収率は保全の有無で決まる（§7.3）。**詐欺と架空循環だけは例外で、何を取っていても0%。** 予防しか手段がないという一点を、痛みを伴う形で伝える。

### 5.2 兆候（シグナル）の生成

真の状態ごとに、各シグナルの出現確率を定義する。**実装はこの表をそのまま定数にする。**

#### 無料シグナル（案件票に最初から書いてある）

| ID | 内容 | 健全 | 悪化 | 破綻寸前 | 詐欺 | 架空 | 反社 |
|---|---|---|---|---|---|---|---|
| S1 | 支払サイトが業界慣行より長い | 10% | 45% | 60% | 70% | 30% | 10% |
| S2 | 前回より取引額が大幅に増えている（継続のみ） | 15% | 25% | 20% | **90%** | 60% | 20% |
| S3 | 決算書を出さない | 25% | 50% | 70% | 80% | 40% | 60% |
| S4 | 取引の経緯が不明瞭（飛び込み・ネット経由） | 15% | 20% | 25% | 60% | 50% | 55% |
| S5 | 納期を急いでいる | 20% | 35% | 40% | **75%** | 30% | 25% |
| S6 | 条件が良すぎる（短サイト・高粗利） | 5% | 10% | 15% | 20% | **70%** | **70%** |

#### 有料シグナル

**登記を確認する（1pt）**

| ID | 内容 | 健全 | 悪化 | 破綻寸前 | 詐欺 | 架空 | 反社 |
|---|---|---|---|---|---|---|---|
| R1 | 本店を短期間に3回以上移転 | 3% | 8% | 10% | **75%** | 20% | 40% |
| R2 | 商号の変更歴がある | 5% | 10% | 12% | **70%** | 25% | 45% |
| R3 | 事業目的に無関係な事業が多数並ぶ | 8% | 12% | 15% | **65%** | 35% | 50% |
| R4 | 役員が最近まとめて入れ替わった | 4% | 15% | 25% | **60%** | 20% | 45% |
| R5 | 設立は古いが実体が新しい（休眠会社の痕跡） | 2% | 5% | 5% | **70%** | 15% | 35% |

**現地を確認する（1pt）**

| ID | 内容 | 健全 | 悪化 | 破綻寸前 | 詐欺 | 架空 | 反社 |
|---|---|---|---|---|---|---|---|
| F1 | 事務所に人がほとんどいない | 3% | 20% | 45% | **70%** | 50% | 40% |
| F2 | 商品が動いた形跡がない | 2% | 8% | 15% | 40% | **95%** | 30% |
| F3 | 稼働しており、在庫も動いている | 85% | 60% | 35% | 15% | 3% | 40% |

**信用調査を依頼する（2pt）**

| ID | 内容 |
|---|---|
| C1 | 信用スコア（真の状態に応じた分布から1つ引く。**幅がある。断定はできない**） |
| C2 | 他社への支払遅延の噂（悪化45% / 破綻寸前80% / その他10%） |
| C3 | 反社会的勢力との関係（反社のみ 90%。他は0%）**＝確定** |
| C4 | 休眠会社の買収（詐欺 85% / 他 3%）**＝確定に近い** |

**同業に聞く（1pt）**

| ID | 内容 |
|---|---|
| G1 | 「あそこは支払いが遅い」（悪化50% / 破綻寸前75% / 健全8%） |
| G2 | 「うちも取引しているが問題ない」（健全70% / 他30%） |

> **G1・G2 は 30% の確率で誤情報になる。** 噂は安いが当てにならない、という実務の感覚を残す。誤情報だったことは答え合わせで開示する。

### 5.3 確定矛盾 ―― 「見つけた！」の瞬間

以下の組み合わせが揃うと、画面に**確定矛盾**として明示され、真の状態が断定できる。

| 組み合わせ | 断定される状態 |
|---|---|
| R1 + R2（本店の移転歴 ＋ 商号の変更歴） | 取り込み詐欺 |
| R5 + C4（休眠会社の痕跡 ＋ 買収の確認） | 取り込み詐欺 |
| R3 + S2 + S5（雑多な事業目的 ＋ 急な増額 ＋ 急ぎ） | 取り込み詐欺 |
| F2 + S6（商品が動いていない ＋ 条件が良すぎる） | 架空循環取引 |
| C3（反社関係の確認） | 反社会的勢力 |

**単独のシグナルでは決して断定できない。**「本店を3回移転している」だけの健全な会社は毎ラン混ざる（§5.4）。組み合わせで初めて黒になる。

これが「兆候を見つける作業」ではなく「**兆候の意味を切り分ける判断**」を生む。

### 5.4 「怪しいが本物」を必ず混ぜる

各ランに、**確定矛盾に1つ足りない健全な会社**を3〜5社混ぜる（R1 は持つが R2 は持たない、など）。

これがないと「兆候があれば断る」が万能の正解になり、調査する意味が消える。断ってしまうと、答え合わせで「この会社は健全だった。他社が受け、取引は続いている」と表示される。**過剰な慎重さのコストを可視化する。**

### 5.5 継続案件 ―― 信用は積み上がり、積み上がった相手が飛ぶと痛い

一度受けた相手からは、翌月以降に**継続案件**が来ることがある（健全なら70%、それ以外は状態に応じて）。

- 継続案件は**その相手の履歴が見える**（過去の支払い実績、これまでの取引額）
- 実績が良いほど大きな額を求めてくる
- **取り込み詐欺は、この仕組みを使って助走する**。小口を数回きっちり払い、頃合いを見て S2（大幅な増額）と S1（長いサイト）を出してくる

**「実績の良さは信用の証明にならない」**という §4.9 の学びが、シナリオではなくシステムで再現される。しかも助走の長さが毎回変わるので、暗記が効かない。

## 6. 情報を買う

**月3ポイント。** 案件が3件あれば、信用調査（2pt）を1件に打つと残りは1ptしかない。

| 手段 | コスト | 分かること | 実費 |
|---|---|---|---|
| 登記を確認する | 1pt | R1〜R5。**確定矛盾の主要な供給源** | 数千円 |
| 現地を確認する | 1pt | F1〜F3。架空循環の決め手 | 交通費 |
| 同業に聞く | 1pt | G1・G2。安いが30%誤る | 0円 |
| 信用調査を依頼する | 2pt | C1〜C4。反社と詐欺の確定 | 数万円 |

**ポイントを繰り越せない**ので「今月は誰を疑うか」が毎月の判断になる。

> v3 では調査結果が翌ターンに出る仕様だったが、**v4 では即座に出す。** 決着を速くする方針を優先する。「調べる時間がない」という緊張は、ポイントの有限性で作る。

## 7. 判断

### 7.1 3つの選択肢

| 選択肢 | 得るもの | 失うもの |
|---|---|---|
| **受ける** | 金額を自分で決める。粗利が入る | 焦げれば原価が消える |
| **現金前払いを要求する** | リスクゼロで粗利が入る | **55%で失注**（相手が良いほど断られやすい） |
| **断る** | 何も失わない | 何も得ない。経費は毎月出ていく |

**金額はプレイヤーが決める。** 相手の希望額より小さくして受けることもできる（＝賭け金を下げる）。ただし希望額の50%を下回ると60%の確率で失注する。

**「限度額」の教育要素は継続案件で効く。** 同じ相手への残高が積み上がるので、「この相手にいくらまで残高を許すか」を考えることになる。残高は取引先一覧に常時表示する。

### 7.2 保全の要求 ―― これ自体が無料の調査になる（v4 の新機軸）

受けるとき、保全を要求できる。

| 保全 | 焦げたときの効果 | 相手が渋る度合い |
|---|---|---|
| 期限の利益喪失条項 | 回収率 +5pt | 低 |
| 所有権留保 | 回収率 +20pt | 低 |
| 公正証書（債務承認弁済契約） | 回収率 +30pt。裁判なしで差押えへ | 中 |
| 連帯保証人（極度額の入力が必須） | 回収率 +35pt。**極度額が未入力なら無効** | 高 |
| 物的担保 | 回収率 +45pt | 高 |

**要求したときの反応が、そのまま兆候になる。**

| 真の状態 | 反応 |
|---|---|
| 健全 | 重い保全は渋る。**35%で交渉が決裂して失注する** |
| 資金繰り悪化・破綻寸前 | ほぼ何でも飲む（売りたいので） |
| **取り込み詐欺** | **二つ返事で全部飲む。**ただし担保の登記や保証人の面談は「後日」と言って引き延ばす |

**「全部あっさり飲む相手は、むしろ危ない」。** これは実務の感覚そのもので、しかもゲームとして強い。リスク（失注）を負って情報を得る、ポーカーのプローブベットと同じ構造になる。

そして**詐欺が飲んだ保全は、決着時にすべて無効になる**（担保物件が存在しない、保証人が架空）。回収率は0%のまま。

> ここが v3 の「予防しか手段がない」を、より痛い形で表現し直したものである。**保全を取ったから安心した、という油断そのものを罰する。**

### 7.3 回収率の決まり方

```
回収率 = 基準回収率（真の状態から。§5.1）＋ 保全のボーナス（合計）
         ただし 0〜95% でクリップ
詐欺・架空循環は、保全に関わらず 0%
連帯保証人は極度額でキャップ。極度額が未入力なら +0pt
```

v3 は「最も高い保全1つだけを適用（max）」としていたが、v4 は**加算**にする。保全を複数取ることに意味を持たせ、判断を「取るか取らないか」から「どこまで取るか」に変えるため。上限95%で青天井は防ぐ。

## 8. 決着と答え合わせ

### 8.1 決着のタイミング

支払期日（出荷の2〜4ヶ月後）に判定する。

- 焦げなければ入金。運転資金が戻る
- 焦げたら回収率に応じた額だけ戻り、残りは損失

### 8.2 答え合わせ画面 ―― 本作で最も重要な画面

**焦げたときも、無事に入金されたときも、必ず出す。**（成功時も出すのが要点。「なぜ正解だったか」を返さないと、正しい判断が偶然と区別できない）

```
┌────────────────────────────────────────────────────────┐
│ 決着: 株式会社アカツキ商会                             │
│ 450万円を受けた → ✕ 全額が焦げ付いた（回収 0円）       │
├────────────────────────────────────────────────────────┤
│ この会社の正体: 取り込み詐欺                           │
│   小口を4回きっちり支払い、5回目に増額を求めてきた     │
│                                                        │
│ あなたが見ていた兆候                                   │
│   ✓ S2 前回より取引額が大幅に増えている                │
│   ✓ S5 納期を急いでいる                                │
│                                                        │
│ 買わなかった調査で、見えたはずの兆候                   │
│   ✗ 登記（1pt）  → R1 本店を2年で3回移転               │
│                     R2 商号の変更歴あり                │
│                     ★ この2つが揃えば「取り込み詐欺」  │
│                       として確定していました           │
│                                                        │
│ 取っていた保全: 連帯保証人・物的担保                   │
│   → いずれも無効でした。担保物件は他人名義、           │
│     保証人は所在不明。相手が消える類型では、           │
│     保全も回収も効きません。                           │
├────────────────────────────────────────────────────────┤
│ 📖 実績の良さは信用の証明にならない                     │

└────────────────────────────────────────────────────────┘
```

**「買わなかった調査で見えたはずの兆候」を必ず表示する。** これが「次は登記を見よう」という行動変容を直接作る。v3 の「いつまでなら取れたか」の後継であり、今度は**プレイヤーが兆候を見ているので機能する**。

### 8.3 断った相手も追跡する

断った相手の**その後**を、1〜3ヶ月後に噂として返す。

- 「断った○○社、先月飛んだらしい」→ **回避した損失**として加算
- 「断った○○社、順調に伸びているらしい」→ **逃した粗利**として加算

両方をスコア画面に出す。**慎重さにも代償があることを、数字で見せる。**

### 8.4 反社会的勢力

反社の相手と取引すると、焦げはしない（きちんと払う）。**その代わり、3ヶ月後に発覚し、以後のランで案件数が25%減る**（取引先が離れた、という扱い）。

信用調査（2pt）を打っていれば C3 で確実に分かる。**「調査は費用ではなく保険である」**を、最も分かりやすい形で表現する。

## 11. モード

### 11.1 キャンペーン（既定）

3年（3ラン）。§9.2 の段階で開放。

### 11.2 デイリー ―― 1日1件

**その日のシードで生成した案件を1件だけ**出す。全プレイヤーが同じ問題を解く。

- 調査ポイントは 3pt
- 判断したら**即座に結果**が出る

## 13. 実装方針

| 項目 | 方針 |
|---|---|
| 形態 | 単一のHTMLファイル。外部依存なし（v3 と同じ） |
| ファイル | **`index.html` を新規に作り直す。**v3 の実装は `archive/kakeuri3.html` として残し、README からリンクする |
| 数値の管理 | §4・§5 の表をファイル先頭の定数オブジェクトに写す。**シグナルの確率表は編集しやすい形にする**（バランス調整の主戦場になる） |
| 乱数 | シード付き（mulberry32）。デイリーは日付をシードにする |
| 保存 | ラン単位。localStorage に1スロット |
| 検証 | `tools/selftest.mjs` を作り直す。**確率モデルの検証を主にする**（10万回試行して、無差別受注が赤字・完全識別が黒字になることを確認する） |

### 実装後の確認項目

1. 無差別に全件受けると、12ヶ月で必ず赤字になる（§4 検算2）
2. 健全のみを受けられれば黒字になる
3. 確定矛盾が揃った案件は、必ず詐欺・架空・反社のいずれかである（**偽陽性が絶対に出ない**こと）
4. 確定矛盾に1つ足りない健全な会社が、毎ラン3〜5社出る
5. 長サイトの案件を続けて取ると、黒字のまま運転資金が尽きる（黒字倒産）
6. 取り込み詐欺は、助走の回数と増額の倍率が毎回変わる
7. 詐欺の相手からは、保全を全部取っていても回収0%になる
8. 連帯保証人の極度額を空欄のまま進めると、回収時に +0pt になる
9. 答え合わせ画面に「買わなかった調査で見えたはずの兆候」が必ず出る
10. 断った相手のその後が、1〜3ヶ月後に必ず返る
11. 1件あたりの判断が30秒〜1分、1ランが15〜20分に収まる
12. 調査ポイント3ptでは、月3件を全部は調べられない

## 付録A: 未確定の論点

実装前に決める必要がある。**現時点では決めていない。**

1. **タイトル。** 「掛売り三年」は36ヶ月が前提だったので、12ヶ月×3年の構成に合わなくなった
2. **相殺をどう戻すか。** v3 では「仕入先を兼ねる相手から仕入れる」という能動的な仕掛けで面白かったが、仕入を廃止したので置き場がない。案件に「この相手からは当社も仕入れている」という属性を確率で付け、回収率 +25pt とするのが最小の案
3. **手形をどう残すか。** サイトの長さとして抽象化すれば足りるが、「支払日に現金化されない」という固有の学びは薄まる。実効サイトの内訳表示で足りるかどうか
4. **難易度のスケーリング。** 3年を通すなら、年ごとに経費や案件規模を上げるか、それとも状態の構成比だけを変えるか
5. **デイリーの成績共有の形式。** ネットワークを使わない前提なら、絵文字グリッド（Wordle形式）で自己申告になる

## 付録B: v3 の実装から得られた知見

捨てる実装からも、確かめられたことがある。**再実装で同じ轍を踏まないために記録する。**

1. **入金を出荷より先に処理しないと、「限度額 ÷ 実効サイト＝月次出荷可能額」が成り立たない。** v3 では出荷を先にしたため、初期の売掛残高が枠を埋めて出荷が止まり、収支が崩壊した。v4 は単発案件なので発生しないが、継続案件の残高管理で再発しうる
2. **粗利率が薄い設定では、原価の上昇を自動で一部転嫁しないとゲームが即死する。** v3 は営業利益率1.25%だったため、原価が5%上がるだけで赤字になった。v4 で粗利率を案件ごとの定数にしたのはこのため
3. **確率的な事故を「教材」にするには、事故の直後に必ず説明を出す必要がある。** v3 は事故をログの一行で流していたので、何が起きたか分からなかった。v4 の答え合わせ画面はこの反省から来ている
4. **画面数とモーダル種別が増えると、それ自体が難易度になる。** v3 は6画面＋モーダル7種で、プレイヤーがどこを見ればよいか分からなかった。v4 は3画面に絞る
