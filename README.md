# 掛売り三年

掛取引（掛売り）の商習慣と、債権の保全・回収に関わる法令を、遊びながら学ぶための会社経営シミュレーションゲーム。

関東の中堅食品卸「株式会社カケウリ商事」の二代目社長として、**36ヶ月を、会社を潰さず・焦げ付きを出さずに乗り切る**。

## 遊び方

**▶ https://aki2ba.github.io/kakeuri_game/**

ブラウザで開くだけ。ビルドもサーバも不要で、外部への通信は一切ない（CDNも外部フォントも使っていない）。進捗はブラウザのローカルストレージに1スロットで自動保存される。

リポジトリを clone した場合は `index.html` をそのままブラウザで開けばよい。`file://` でも動く。

タブレット以上の画面幅を想定している。ライト／ダークの両テーマに対応（右上の「◐ テーマ」で切り替え）。

## この3つを体で覚えるゲーム

1. **黒字でも現金が尽きれば倒産する**（利益と現金は別物。手形と長期サイトがこれを引き起こす）
2. **支払条件は値段と同じくらい重要**（「いくらで売るか」より「いつ入るか」で会社が死ぬ）
3. **焦げてからできることは、焦げる前に何をしたかで決まる**（担保も保証人も公正証書も、危なくなってからでは取れない）

3番目が中核である。回収画面には「使えない手段」が並び、それぞれに**いつまでなら取れたか**が具体的なターンとポイントで表示される。

### 自己テスト

```sh
node tools/selftest.mjs          # 確認項目のアサーション（DOMは最小スタブ）
node tools/selftest.mjs --sim    # ＋ 10シードの通し実行でバランスを確認
```

検証している主なもの: 支払サイトのガード条件（§4.1）、限度額 ÷ 実効サイトの換算（§6.4）、保全状況別の基準回収率と max 規則（§6.9(c)）、極度額未設定の連帯保証が無効になること（§5.7）、取り込み詐欺・架空循環取引で回収率が0%になること、開放前の機能を「取れました」と表示しないこと（§3.5）、総与信枠のゼロサム性（§4.4）、解説カードの構成（§8）、全画面・全モーダルが例外なく描画されること。

## GitHub Pages の公開設定

`index.html` がリポジトリ直下にあるので、そのまま静的サイトとして公開できる。既定ブランチ（`master`）に push すると `.github/workflows/pages.yml` が走り、セルフテストが通れば https://aki2ba.github.io/kakeuri_game/ に公開される。

`configure-pages` に `enablement: true` を渡しているので、**Pages が未設定でもワークフロー自身が有効化する**。手作業の設定は基本的に要らない。

### 前提: リポジトリの可視性とプラン

**非公開リポジトリで Pages を使うには GitHub Pro / Team / Enterprise が必要**である。Free プランの非公開リポジトリでは Pages を有効化できず、`configure-pages` が次のエラーで落ちる。

```
Get Pages site failed. Please verify that the repository has Pages enabled
and configured to build using GitHub Actions ... Error: Not Found
```

このエラーが出たら、対処は次のどちらか。

- **リポジトリを公開に切り替える**（Settings → General → Danger Zone → Change repository visibility）。Free プランでも Pages が使える
- **有料プランにする**。非公開のまま公開ページを持てる（サイト自体は誰でも見られる状態になる点は同じ）

有効化できたあとは、**Settings → Pages → Source** が「GitHub Actions」になっていることを確認すればよい。手動で「Deploy from a branch」（`master` / `(root)`）を選んでも公開できるが、その場合は公開前のセルフテストが走らない。

`.nojekyll` を置いてあるので、Jekyll による処理は行われずファイルがそのまま配信される。

## 実装上の判断（設計書との差分）

設計書は実装を含まないため、実装時に決めた点と、意図的に設計値から動かした点を記録する。

| 箇所 | 判断 |
|---|---|
| **ターン内の処理順** | 設計書 §3.2 は ③出荷 → ④入金 の順だが、実装は**④入金 → ③出荷**とした。期日到来分を落としてから与信枠の空きを見ないと、教材の中心である「限度額 ÷ 実効サイト ＝ 月次出荷可能額」（§6.4）が成り立たず、月商の2ヶ月分を出荷できなくなるため。画面にもこの順序を明記している |
| **架空循環取引の金額** | 設計書 §4.10 の「1件5,000万円」は、末締め翌月末で2ヶ月分が滞留すると1億円の焦げ付きになり、その時点で必ず即死する。学習ビート（乗る → 気持ちよく儲かる → 破綻）が成立するよう **1件1,500万円**に下げた |
| **仕入原価の上昇** | 上昇幅を1回あたり4〜10%（原価指数の上限1.35）とし、**上昇分の5割は自動的に売価へ乗る**ものとした。営業利益率1.25%の設定（§2.4）では、原価上昇が一切転嫁されないと数ターンで確実に破綻するため。残り5割が価格転嫁交渉の対象になる |
| **価格改定の一括通告** | §6.8 の「価格転嫁を交渉する」（取引先ごと・成功60%）に加え、**「全取引先に価格改定を通告する」**（アクション枠1・7割が受け入れ、飲まない相手は発注を5%減らす）を追加した。取引先が10社を超えると、個別交渉だけではアクション枠3で原価上昇に追いつけないため |
| **支払サイト早見表** | ダッシュボードに、締め日・支払月・支払日を選んでサイトを計算する早見表を置いた。§4.1 のガード条件（「末締め・当月末払い」は成立しない）にプレイヤーが触れられる場所が他にないため。成立しない組み合わせを選ぶと解説カードが出る（確認項目6） |
| **法的整理の結末** | 法的整理に入った時点では確定させず、**2ターン後に確定**する。その間に担保の実行・連帯保証人への請求・相殺・債権届出を打てる。§6.7 が「連帯保証人に請求」「担保を実行」を*基準回収率を発動させるアクション*と定めているため、打つ機会が必要になる |
| **解説カードの層** | 全30枚・必須14枚（§8.1）。必須はその場でモーダル表示、詳細は用語帳のみ。設計書の発火条件をすべて満たすと必須が14枚を超えるため、督促／シェアの罠／配当順位／登記の危険信号／在庫／手形ジャンプを詳細層に回した |
| **回し手形の振出人倒産** | 罠プールの1種（§7.3）として、受取手形が不渡りになり1割しか回収できないイベントとして実装した |
| **乱数** | シード付きの決定論的な乱数（mulberry32）。シードと消費回数を保存するので、読み込み後も同じ乱数列が続く。罠の種類・対象・発火ターンは新規開始のたびに変わる（確認項目14） |

## 難易度について

営業利益は月50万円（売上高営業利益率1.25%）しかない。**1社の焦げ付きが1年分の利益を吹き飛ばす**という緊張は演出ではなく、この収支構造から自動的に出てくる。倒産は珍しくないし、黒字倒産を一度経験することは設計上の狙いでもある。

`node tools/selftest.mjs --sim` の通し実行（保全を取り、回収を打ち、価格転嫁を回し、枠を剥がして新規を入れる方針）で、36ターン到達がおよそ6割。到達した回はいずれも評価「優」（焦げ付き純損失が1,500万円かつ累計売上の1.0%以内）になる。**保全を取ったか取らなかったかが、そのまま優・良の分かれ目になる**（§3.4）。
