掛取引の商習慣と、債権の保全・回収に関わる法令を、遊びながら学ぶためのゲーム。

## いまの状態

**設計を v4 に書き直しました。実装はこれからです。**

v3（「掛売り三年」）は完成し、遊べる状態まで実装しましたが、**面白くありませんでした**。原因は3つとも構造的なもので、部分的な手直しでは直らないと判断しています。詳しくは [`docs/design.md` §0](docs/design.md) に書きました。要約すると:

1. **スコアという結論を渡して、照合できる根拠を渡していなかった** → 「どう判断すればいいか分からない」
2. **1件の判断の決着まで9〜22ターン、しかも1ターンが重かった** → 結果が返るころには何を判断したか憶えていない
3. **伏線は仕込んで動いていたが、回収する側に記憶がなかった** → 1 に依存していて単独では空振りする

v4 は「**見抜きはシステム生成、判断は賭け、結果は経営に返す**」という方針で、1判断30秒〜1分・1ラン15〜20分に作り直します。

## v4 の要点

詳細は [`docs/design.md`](docs/design.md)。核になるのは次の3つです。

**兆候は2層にする。** 書類間の論理的な食い違い（＝**確定矛盾**。見つければ黒が確定する）と、危険度を動かすだけの**確率兆候**を分ける。実務の与信もこの2層で、詐欺は矛盾で見抜き、資金繰りの悪化は兆候の積み重ねで推し量る。別の技術なので、ゲームでも別の層にする。

**保全の要求そのものを、無料の調査にする。** 健全な相手は重い保全を渋り、35%で失注する。資金繰りが苦しい相手はほぼ何でも飲む。取り込み詐欺は**二つ返事で全部飲む**（どうせ払う気がない）。「あっさり飲む相手ほど危ない」という逆説が生まれ、リスクを負って情報を取るポーカーのプローブベットと同じ構造になる。そして詐欺が飲んだ保全は、決着時にすべて無効になる。

**答え合わせ画面を最重要の画面にする。** 決着のたびに、真の状態・自分が見た兆候・そして**買わなかった調査で見えたはずの兆候**を並べる。「登記（1pt）を見ていれば、本店3回移転と商号変更が揃って詐欺と確定していました」まで書く。これが次の行動を直接変えます。

## GitHub Pages

`index.html` がリポジトリ直下にあるので、そのまま静的サイトとして公開されます。`master` に push すると `.github/workflows/pages.yml` が走り、セルフテストが通れば公開されます。

### 最初に1回だけ必要な設定（実施済み）

**Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** にする。ブラウザからしかできません（GitHub のモバイルアプリにはリポジトリ設定の画面がありません）。

ワークフローには `configure-pages` の `enablement: true` を付けてありますが、**Pages サイトが存在しない状態からの「作成」は Actions の `GITHUB_TOKEN` では実行できません**。`permissions: pages: write` を与えても `Create Pages site failed. Error: Resource not accessible by integration` になります。管理者権限の PAT をシークレットに登録すれば自動化できますが、設定を1回開くほうが早いです。

また、**非公開リポジトリで Pages を使うには GitHub Pro / Team / Enterprise が必要**です（このリポジトリは公開なので Free プランで動いています）。公開されたページは可視性やプランに関わらず、URL を知っていれば誰でも見られます（制限できるのは Enterprise Cloud のみ）。

`.nojekyll` を置いてあるので、Jekyll による処理は行われずファイルがそのまま配信されます。
